# 协作设计

## 目标

把用户目标、可检查的成果、模型意见和具体行动接在同一个循环中。输入一次，按任务选择投入；重要问题需要实际处理，验收以当前成果与证据为依据。

## 模块

| 模块 | 职责 |
|---|---|
| `codex_conductor.py` | Tkinter 界面、任务选择、阶段与成果呈现 |
| `conductor_core.py` | 路由、调度、验收、恢复、资源锁、SQLite 记录 |
| `codex_bridge.py` | Codex app-server、本轮消息身份、原回合查询 |
| `harness_bridge.py` | Harness 本机发现、授权连接、请求与流恢复 |
| `app_paths.py` | 安装资源与运行数据路径 |
| `agent_link.py` | 命令行调用入口 |
| `build_release.py` | Windows 程序与允许清单分享构建 |

## 状态与恢复

任务、阶段消息、行动记录、证据和实际文件分别保存。恢复先检查原任务、目录、对话与文件身份，复用确定完成的阶段。可能已经执行写入但缺少确认的操作先核对，不直接重新提交。

多个项目可以并行；同一项目目录、父子重叠目录或同一复用对话互斥。顺序文件交接由协调器安排，保存前后哈希和备份，再由主导者核验。

## 进展与证据

对文本成果，比较成果文本版本；对已经保存的文件成果，比较协调器读回的文件哈希。哈希变化说明内容发生变化，成果是否更好仍由验收与独立检查判断。

完整证据记录与原始材料身份分别计算。结论转述或自报核验标签变化可以留在账本里，但不会单独算作新增原始证据。来源分组用于呈现依赖关系，当前分组标签由执行者提供；它不是自动判定来源独立性的算法。

每轮相对上次实际审过的行动计算进展，防止旧改动被反复计为新改进。持续停滞时切换到实际核证或更换方法。必做验收、重大未解决问题和外部阻塞继续约束交付。

## 后续演进

优先拆分证据与验收等纯逻辑模块，再处理提供方抽象；由回归保护接口。当前核心模块较集中，不能仅凭行数认定为冗余并直接删代码。
